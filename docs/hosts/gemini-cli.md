# Installing deliberation in Gemini CLI

The repo root carries a [Gemini CLI extension](https://geminicli.com/docs/extensions/)
manifest, `gemini-extension.json`. It is generated by `scripts/sync-hosts.js` and its
version follows each release.

## Install

```bash
gemini extensions install https://github.com/antonbabenko/deliberation
```

Add `--ref v<version>` to pin a release. Restart Gemini CLI after the install.

The extension does three things:

- Starts the MCP server from the installed copy with `node ${extensionPath}/server/mcp/index.js`.
  It has no npm dependencies, so there is no `npm install` step. It needs `node` on `PATH`.
- Loads `docs/tool-guide.md` as context, so the model knows when to call each tool.
- Asks for the optional provider keys below.

Check it with `gemini extensions list` and `gemini mcp list`. The `deliberation` server
should show `Connected`. Gemini CLI starts stdio MCP servers only in trusted folders.

## Provider credentials

Gemini CLI does not pass environment variables with names like `*KEY*` or `*TOKEN*` to an
extension's MCP server. It passes only the ones the manifest declares. The manifest declares
two, and the install asks for both:

| Setting | Provider | If blank |
|---------|----------|----------|
| `XAI_API_KEY` | Grok | Grok is off |
| `OPENROUTER_API_KEY` | OpenRouter | OpenRouter is off |

Set or change them later with `gemini extensions config deliberation`. Sensitive values go
to the system keychain.

The other providers do not need a key here:

- GPT: log in once with `codex login` (or `codex login --device-auth`). `CODEX_API_KEY` and
  `CODEX_ACCESS_TOKEN` from your shell do not reach the server.
- Gemini: sign in to the Antigravity CLI (`agy`).

The deliberation config file (`~/.config/deliberation/config.json`) works as on every other
host.

## Updating

```bash
gemini extensions update deliberation
```
